# ADR-0005：网络设备实验的模拟方案取舍

- 状态：已接受
- 日期：2026-09-23（补记；决策随网络模块落地）
- 关联：RUNBOOK §15（约定范围：不采购真机或商业镜像授权）

## 背景

网络模块（探测矩阵 + 设备配置备份）需要"网络设备"作为被管对象。约束：
宿主 WSL2 仅 6GB 内存、个人项目无真机预算、第一版明确不采购真机或商业镜像授权。
发挥网络工程背景的正确姿势是把管理面自动化（备份/审计/连通性）做扎实，而不是
复现数据面。

## 候选与取舍

| 方案 | 判断 |
|---|---|
| 真机（二手交换机/路由器） | 预算、体积、噪音与供电不适合宿舍/桌面环境，否 |
| EVE-NG / PNETLab + 商业镜像 | 镜像授权不合规（约定范围明确排除），镜像体积数十 GB，否 |
| GNS3 全量模拟 | 控制面/数据面都能跑，但 QEMU 节点内存大（单节点数百 MB 起），6GB 预算放不下，否 |
| **容器模拟（FRR）** | frrouting 官方镜像 + openssh 派生，单台实测 ~40MB，管理面真实，采纳 |

## 决策

- **镜像**：`frrouting/frr:latest`（Alpine 3.16.2 / FRR 8.4）派生 `opsforge-frr:1.0`——
  官方镜像无 sshd（`which sshd` 为空），加装 openssh-server，ops 用户入 frr/frrvty
  组以运行 vtysh；entrypoint 覆盖后回官方 `docker-start` 保信号转发。
- **采集**：netmiko 4.6.0 `linux` 驱动 SSH + `vtysh -c 'show running-config'`（FRR
  无 netmiko 原生驱动，`send_command_timing` 不依赖 prompt 探测，剥 `%` 警告行即可）。
- **可重复性**：种子配置 `frr.conf` 只读挂载，运行态变更（vtysh conf t）重启即回种子；
  备份/变更审计实验可以无限重放。
- **规模**：r1/r2 两台足够演示"变更→检出→diff→回溯"全链路。

## 后果

- ✅ 全链路实测：配置变更 22s 检出、unified diff 精确、任意版本内容回溯（实验与
  验收用例覆盖）。
- ✅ netmiko 依赖树 pip-audit 零已知洞；单台 40MB，预算无压力。
- ✅ CLI 是真实 FRR（生产在用的路由套件），vtysh 语法/配置结构可迁移到真实设备。
- ⚠️ Cisco 与 FRR 语法差异存在（netmiko 驱动不同）；实验聚焦管理面，数据面转发
  （路由收敛、组播）不在第一版范围内（如实界定）。
- ⚠️ FRR 容器 `privileged`（FRR 需要网络权限），仅限本地实验环境。
